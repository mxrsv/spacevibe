# SpaceVibe: Clean

Date: 2026-11-18
Status: draft, 2026-11-20. Absorbed by the [app-wide redesign spec](2026-11-20-spacevibe-redesign.md) (RD18): CL1–CL4 and CL-R1–CL-R8 stay in force there; the UI placement follows that spec.
Parent: [PRODUCT.md](../../PRODUCT.md) job 1 (Clean up, D38). Builds on the per-row Remove of [D24](2026-11-06-spacevibe-linear-identity-decisions.md) and the journal and trash of [mutations.md](../internals/mutations.md).

## Intent

- **Outcome:** one place where the owner cleans up whatever Claude Code and Codex leave behind on disk. That covers unused equipment (Skills, Subagents, Hooks), old session logs, and caches. Each group shows how much it frees, and every removal can be undone.
- **User:** the owner. Today the CLI folders hold `~/.claude` 12G, with `projects/` at 12G, and `~/.codex` 5.1G, with `packages/` 1.6G, `sessions/` 1.3G and `thread_history_1.sqlite` 919M (`du -sh`, 2026-11-18).
- **Why:** removing items one row at a time does not scale to dozens of them, and nothing in the app touches the gigabytes of logs and caches.

## Requirements

- **CL-R1. Equipment in bulk (CL1, CL4).**
  - Lists every Skill, Subagent and Hook in the Never ran or Dead state across both CLIs.
  - Plugin-owned items and managed settings are listed as read-only and cannot be selected (`PRODUCT.md`).
  - Multi-select. An item that carries the "added …" note (D63) starts unselected.
  - One Remove for the selection makes one journal entry, and one Undo restores the whole batch, all or nothing. It reuses the existing remove paths (`loadout.removeItem`, `loadout.removeDeadHooks`) under one lock.
- **CL-R2. Session logs (CL1, CL2).**
  - Logs are listed per CLI and by age: older than 30, 90 or 180 days. Each bucket shows its file count and size.
  - Files are found only through `logs.Walk`, so `.jsonl.zst` rollouts are included and nothing is counted twice ([usage.md](../internals/usage.md#rules-that-are-easy-to-get-wrong)).
  - Only session log files move. Everything else under `~/.claude/projects/<p>/` stays, `memory/` included.
  - Codex SQLite databases (`thread_history_*.sqlite`, `state_*.sqlite`, `logs_*.sqlite`) are never moved, because they are live databases owned by the CLI.
- **CL-R3. Usage survives a log's removal (CL3).**
  - Before a log moves, the core writes the scan records of that log into an archive in its own data folder. The usage scan and Activity's token and cost totals merge that archive with the live logs.
  - The archive holds names, days, hook hashes, durations and token counts per model, never log text (S-R3).
  - Undo removes the archived records together with the move, so nothing is counted twice.
  - A session whose log has moved no longer opens in Activity. Only its totals remain, and the UI says so.
- **CL-R4. Caches (CL1, CL2).**
  - The core holds a fixed allowlist of cache paths per CLI. A path joins the list only after its meaning is checked against the CLI's docs or behaviour (UP6). Candidates include Claude `file-history/`, `shell-snapshots/`, `paste-cache/`, `telemetry/`, `cache/`, and Codex `cache/` and `packages/` versions other than the one in use.
  - A path that has not been verified is not shown.
- **CL-R5. Where removed files go and how they come back (CL2).**
  - Logs and caches move to the macOS Trash. The core records each resulting path, and Undo moves the files back.
  - Equipment keeps the app's own trash (`<data>/trash`), as it does today.
  - Logs and caches of a CLI cannot be removed while Activity reports a running session of that CLI. The disabled control says why.
- **CL-R6. Sizes are real (W23).**
  - Every size shown is computed by the core from the exact files the action will move.
  - After the move, the result shows the bytes actually moved, not the estimate.
- **CL-R7. Safety.**
  - Every path is contained under the CLI root it came from, and no symlink is followed.
  - Under `SPACEVIBE_TEST=1` the real-home guard refuses as it does for other writes (S-R1).
  - The app executes nothing (S-R4).
- **CL-R8. Docs.** The change that ships CL-R2 updates the write limit in `PRODUCT.md`, the S-R rules in `AGENTS.md`, and [mutations.md](../internals/mutations.md).

## Inferred, not decided

- **Placement:** a `Clean` entry in the sidebar, with three groups (Equipment, Logs, Caches). Source: agent's choice. The mock decides it.
- **Age buckets of 30, 90 and 180 days.** Source: agent's choice.
- **`.cursor` and `.gemini` are out of scope** until the engine supports those CLIs: decided by the owner 2026-11-21 ("nhận hết", redesign spec RD42), narrowing CL1.

## Out of scope

- Moving or compacting the Codex SQLite databases.
- Scheduled or automatic cleaning.
