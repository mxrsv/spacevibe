## Approach

- **Two-step core change.**
  - Step 0a moves every per-CLI fact behind one registry and one adapter interface per subsystem, without changing any output. The byte-identical goldens prove it.
  - Step 0b then changes the wire shape alone, so a golden diff in 0b can only come from the shape.
- **Adapter seams follow the existing packages.** Each package that branches on the CLI today gets a per-CLI implementation behind a small interface owned by that package. The registry entry lists which of them a CLI provides:
  - `roots`: resolve roots.
  - `inventory`: read items and hook events.
  - `mutate`: writers, plus the containment roots.
  - `usage`: log line parser.
  - `activity`: fold and live pid.
  - `limits`: reader.
  - `proc`: process match.
  
  A missing implementation means the concept is absent (MC-R5). It never falls back to another CLI.
- **Waves reuse one template** (W-T1 to W-T8 below). The only per-wave work is one adapter folder, one fixture subtree, the registry entry, the mark and the copy.
